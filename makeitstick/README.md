# Make It Stick — applied to this course

Based on *Make It Stick: The Science of Successful Learning* by Peter C. Brown,
Henry L. Roediger III, and Mark A. McDaniel (Harvard University Press, 2014).

The book is not included here — it's a commercially published book, so buy or
borrow it. This folder is a working summary of its findings and, more
importantly, a concrete protocol for running [`../docs/plan.md`](../docs/plan.md)
the way the research says you should.

## The one-paragraph version

Learning feels most productive exactly when it is least effective. Rereading and
highlighting produce fluency with the *text*, which your brain misreads as
mastery of the *material*. What actually builds durable memory is effortful
retrieval: closing the book and trying to reconstruct the answer, spacing those
attempts out until they're slightly hard, and mixing topics rather than drilling
one to fluency. These feel worse and work better.

## Why this matters for git specifically

Git is unusually vulnerable to the illusion of knowing. Cheatsheets are
everywhere, so you can look up `git reset --hard` forever and never encode it.
And the moments you most need git — a botched rebase, a conflicted merge at
5pm — are exactly the moments you're least able to calmly search.

The failure mode is predictable: you read a tutorial, everything makes sense,
and three weeks later you're pasting commands you don't understand into a
terminal on a repo that matters. The fix is to make yourself retrieve, cold,
before you look.
